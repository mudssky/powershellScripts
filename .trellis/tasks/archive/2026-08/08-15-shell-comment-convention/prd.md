# 统一 Shell 配置注释规范

## Goal

为 `shell/` 下仍在维护的配置与部署脚本建立统一、可审查的注释层级，使维护者能快速识别文件职责、配置主题边界、函数契约和局部设计原因，并在不改变任何 Shell 行为的前提下完成现有文件迁移。

## Background

- `shell/shared.d/node.sh:17-32` 中 `PNPM_HOME` 默认值补齐与 PATH 注入属于同一 pnpm 配置主题，但当前两个条件块只有各自的单行注释，缺少共同边界。
- `shell/shared.d/node.sh:34-143`、`tmux.sh`、`zellij.sh` 和 `bluetooth.sh` 已使用高区分度的函数完整分隔块；`claude-profile.sh`、`vscode.sh`、`path.sh` 等使用紧凑契约；`deploy.sh`、`modern-tools.sh`、`proxy.sh` 使用多种章节标题；其余文件仍有零散或英文注释。
- `.trellis/spec/shell-shared/package/index.md:53-58` 已要求公共接口具备中文功能、入参、返回值和必要设计意图，但尚未规定文件级、配置块、函数级和局部注释的视觉层级。
- 当前工作区已有用户未提交的 `shell/shared.d/node.sh` 功能改动；本任务必须保留该改动，只调整其注释组织。

## Requirements

### R1. 迁移范围

- 覆盖 `shell/deploy.sh`、`shell/shared.d/**`、`shell/bash.d/**` 与 `shell/zsh.d/**` 中仍在维护的 Shell 文件；当前仓库证据为 32 个脚本文件。

### R2. 注释层级

- 规范必须区分四种语义层级：文件头、配置/章节块、函数契约、局部实现说明。
- 不同层级必须具有不同外形，避免配置章节与复杂函数使用无法区分的同一种装饰。

### R3. 文件头

- 活跃 Shell 文件必须在 shebang 之后（无 shebang 时位于文件首行）说明文件职责。
- 兼容性、加载方式、关键副作用等仅在有维护价值时记录；禁止填写无信息量的固定字段。

### R4. 配置与章节块

- 配置/章节块采用单行横向标题 `# -- <主题> -----`。
- 同一标题后的连续代码直到下一个同级标题或文件结束均属于该主题；块内使用普通单行注释解释具体分支。
- `PNPM_HOME` 默认值补齐与 PATH 注入必须归入同一个 `pnpm` 配置块。

### R5. 函数契约

- 所有函数必须记录摘要、参数和返回码。
- 简单函数使用紧凑契约；公共入口、复杂控制流、非直观副作用、兼容性回退或关键设计约束使用完整分隔块。
- 完整块按实际需要补充设计意图、stdout/stderr 输出和副作用；不得机械堆砌空字段。
- 条件块内的嵌套函数注释必须跟随代码缩进，不得伪装成文件级章节。

### R6. 术语与标点

- 字段名称统一为 `参数：`、`输出：`、`返回码：`、`副作用：`、`设计意图：`。
- stdout/stderr 与退出状态必须分开表达，不再用含混的“返回值”同时表示两者。
- 中文说明使用全角冒号和句号；参数项、输出项和状态码项使用 `$1 — ...`、`stdout — ...`、`0 — ...` 格式。

### R7. 行为保持

- 迁移只允许修改完整行注释和为注释分组所需的空行，不修改命令、变量、条件、函数签名、重定向、引号、shebang 或加载顺序。
- 不得覆盖、回退或重写用户现有的 `shell/shared.d/node.sh` 功能改动。

### R8. 规范落点

- 在 `.trellis/spec/shell-shared/package/` 新增独立注释规范文档，并从现有 `index.md` 链接。
- 规范文档必须包含适用范围、四层模板、函数分级条件、字段语义、反模式和审查清单。

## Acceptance Criteria

- [x] AC1：R1 范围内的全部活跃 Shell 文件已按四层规范迁移，范围外文件无改动。
- [x] AC2：`shell/shared.d/node.sh` 的两个 pnpm 条件块位于同一个单行横向配置标题下，局部注释仍分别解释默认值与幂等 PATH 注入。
- [x] AC3：目标范围内每个函数均具有摘要、参数和返回码；满足 R5 复杂条件的函数使用完整分隔块并包含必要扩展字段。
- [x] AC4：目标范围内不再并存等价的旧式章节标题、旧字段名或中英文标点混用；局部注释不复述显而易见的 Shell 语法。
- [x] AC5：相对于实施前快照，目标文件的所有非注释、非空白可执行行保持不变；`.sh` 文件通过 Bash 语法检查，`.zsh` 文件通过 Zsh 语法检查。
- [x] AC6：新的 Trellis 注释规范已从 `.trellis/spec/shell-shared/package/index.md` 可发现，并覆盖 R8 要求的全部内容。

## Out of Scope

- 修改 Shell 逻辑、命令行为、兼容策略、缩进风格或命名。
- `shell/archive/**`、`shell/.gitignore`、本机私有忽略文件，以及 `scripts/bash/**`、Linux/WSL/bootstrap/FNOS 等其它包。
- 引入 `shfmt`、ShellCheck 或自定义注释 lint 工具。
- 为纯注释迁移新增单元测试、行为测试或变更日志。

## Risks and Constraints

- 目标范围包含函数密集文件；若复杂度判定失控，完整分隔块会造成无意义的纵向膨胀。审查时必须按语义而非函数长度判定。
- `shell/shared.d` 由 Bash/Zsh 共同 source；虽然本任务不改逻辑，仍需语法检查防止注释或空行编辑误伤续行结构。
- 仓库规则允许纯文案/注释改动跳过 `pnpm qa`；本任务以可执行行快照对比和 Shell 语法检查作为行为保持证据。
