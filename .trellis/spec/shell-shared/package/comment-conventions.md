# Shell 活跃脚本注释规范

## 适用范围

本规范适用于以下仍在维护的 Shell 文件：

- `shell/deploy.sh`
- `shell/shared.d/*.sh`
- `shell/bash.d/*.sh`
- `shell/zsh.d/*.zsh`

不适用于 `shell/archive/**`、本机私有忽略文件、`scripts/bash/**` 或其它 Shell 包。

## 四层模板

### 文件头

shebang 保持原样且位于第一行；无 shebang 时从首行开始使用等号边框说明职责。

```sh
#!/bin/bash
# ======================================================================
# 文件：node.sh
# 作用：初始化 Node.js 工具链与 package.json 脚本选择命令。
# 兼容性：Bash / Zsh。
# ======================================================================
```

`文件：`、`作用：`必需；`兼容性：`、`加载方式：`、`副作用：`仅在确有维护价值时添加，不填写无信息量的“无”。

### 配置或章节块

配置章节使用单行横向标题，标题总宽度约 72 列：

```sh
# -- pnpm ---------------------------------------------------------------
```

标题只标识一个顶层主题或生命周期阶段，范围延续到下一个同级标题或文件结束，不使用闭合标题。块内普通单行注释只说明分支原因、兼容约束、幂等性或风险。

### 函数契约

每个函数都必须有摘要、`参数：` 和 `返回码：`。

短小、直接且无隐藏状态的函数使用紧凑契约：

```sh
# _pkg_run_script — 使用指定运行器执行 package.json script。
# 参数：$1 — 运行器名称；$2 — script 名称。
# 返回码：透传包管理器退出码；未知运行器返回 1。
_pkg_run_script() {
  ...
}
```

公共入口、复杂控制流、修改环境/目录/文件/终端状态、stdout/stderr 属于调用合同、兼容性回退或关键设计约束明显的函数，使用完整分隔块：

```sh
# ----------------------------------------------------------------------
# _pkg_find_root — 从当前目录向上查找最近的 package.json 所在目录。
#
# 设计意图：
#   以 package.json 所在目录作为执行目录，避免从子目录运行时相对路径漂移。
#
# 参数：无。
# 输出：
#   stdout — package.json 所在目录的绝对路径。
# 返回码：
#   0 — 找到 package.json。
#   1 — 到达文件系统根目录仍未找到。
# ----------------------------------------------------------------------
_pkg_find_root() {
  ...
}
```

`输出：`只描述 stdout/stderr；环境、全局状态、文件、目录或终端变化写在`副作用：`；只解释方案原因时使用`设计意图：`。无参数写`参数：无。`。嵌套函数的整段注释与函数定义保持相同缩进。

### 局部实现说明

局部注释只说明原因、约束、异常行为或不可见副作用：

```sh
# 使用机器可读输出，避免 ANSI 样式混入真实会话名。
sessions=$(zellij list-sessions --no-formatting)
```

不得逐句翻译显而易见的 Shell 语法，不保留临时编号步骤、“关键修改”等历史记录。中文说明使用全角标点，命令、变量、路径和协议名保持原文。

## 字段语义与标点

统一使用：`参数：`、`输出：`、`返回码：`、`副作用：`、`设计意图：`。条目使用 `$1 — ...`、`stdout — ...`、`0 — ...` 格式；stdout/stderr 与退出状态必须分开表达，不用“返回值”混称。单项字段可同行，多项字段逐行缩进两个空格。

## 函数分级条件

使用完整分隔块的条件满足任一项即可：

- 面向用户的公共命令或主要入口；
- 存在多阶段控制流、解析或降级链；
- 修改环境变量、全局变量、当前目录、终端状态或外部文件；
- stdout/stderr 是调用合同的一部分；
- 存在非直观兼容性约束、幂等要求或关键设计决策。

其它函数使用紧凑契约，避免函数密集文件产生无信息量的边框。

## 反模式

- 并存 `# ===== 标题 =====`、`# --- 标题 ---` 或三行章节块；
- 使用半角字段 `参数:`、`入参:`、`返回:`、`返回值:` 或中英文标点混用；
- 用完整分隔块包装每个简单函数；
- 局部注释复述命令表面语法；
- 在注释中保留临时编号步骤、“关键修改”或开发过程记录；
- 把嵌套函数契约写成文件级章节；
- 修改注释时顺带改动命令、变量、条件、函数签名、重定向、引号、shebang 或加载顺序。

## 审查清单

- [ ] shebang 与所有可执行行保持原样。
- [ ] 文件头使用等号边框，且职责说明位于 shebang 后或首行。
- [ ] 配置章节均使用单行横向标题；同一主题连续归组。
- [ ] 每个函数均有摘要、`参数：` 和`返回码：`。
- [ ] 复杂函数才使用完整分隔块，并按需补充输出、副作用、设计意图。
- [ ] 字段、条目、中文标点符合统一合同。
- [ ] 局部说明解释原因或约束，不复述语法或记录临时步骤。
- [ ] `node.sh` 的两个 pnpm 条件块位于同一 `pnpm` 标题下。
- [ ] 目标范围外文件没有变更。
