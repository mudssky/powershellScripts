# 统一 Shell 配置注释规范设计

## 设计目标

用最少的视觉层级解决两个问题：一眼识别代码属于哪个配置主题；一眼识别函数契约及其复杂度。规范只组织注释，不改变 Shell 运行结构。

## 规范落点

新增 `.trellis/spec/shell-shared/package/comment-conventions.md`，并从 `.trellis/spec/shell-shared/package/index.md` 的开发检查与质量检查位置链接。

`comment-conventions.md` 是 `shell/` 活跃配置文件的注释单一事实来源。`index.md` 继续保留 `shared.d` 的运行时、兼容性和交互命令规范，不复制完整模板。

## 适用边界

包含：

- `shell/deploy.sh`
- `shell/shared.d/*.sh`
- `shell/bash.d/*.sh`
- `shell/zsh.d/*.zsh`

排除：

- `shell/archive/**`
- `shell/.gitignore`
- 被忽略的本机私有文件
- `scripts/bash/**` 与其它 Shell 包

实施前按上述模式重新枚举文件；当前证据显示共有 32 个活跃脚本文件。

## 四层视觉结构

### 1. 文件头

shebang 始终保持第一行。无 shebang 时，文件头从第一行开始。

```sh
#!/bin/bash
# ======================================================================
# 文件：node.sh
# 作用：初始化 Node.js 工具链与 package.json 脚本选择命令。
# 兼容性：Bash / Zsh。
# ======================================================================
```

规则：

- `文件：`、`作用：`必需。
- `兼容性：`、`加载方式：`、`副作用：`仅在有维护价值时添加。
- 不增加或修改 shebang；不填写“无”字段。

### 2. 配置或章节块

```sh
# -- pnpm ---------------------------------------------------------------

# 保留用户显式设置；仅为支持的平台补齐默认目录。
if [ -z "${PNPM_HOME+x}" ]; then
  ...
fi

# 仅在目录存在且 PATH 未包含时追加，保证重复加载幂等。
if [ -n "${PNPM_HOME:-}" ] && [ -d "$PNPM_HOME/bin" ]; then
  ...
fi
```

规则：

- 标题格式固定为 `# -- <主题> `，右侧以 `-` 补齐，目标总宽度 72 列；标题过长时不截断语义。
- 标题只标识一个顶层主题或生命周期阶段，不为每个单独命令创建标题。
- 分组范围延续到下一个同级标题或文件结束；不使用闭合标题。
- 块内局部注释解释分支原因、兼容约束、幂等性或风险，不重复代码表面含义。

### 3. 函数契约

#### 紧凑契约

适用于直接、短小、无隐藏状态的函数。

```sh
# _pkg_run_script — 使用指定运行器执行 package.json script。
# 参数：$1 — 运行器名称；$2 — script 名称。
# 返回码：透传包管理器退出码；未知运行器返回 1。
_pkg_run_script() {
  ...
}
```

#### 完整契约

适用于以下任一条件：

- 面向用户的公共命令或主要入口。
- 存在多阶段控制流、解析或降级链。
- 修改环境变量、全局变量、当前目录、终端状态或外部文件。
- stdout/stderr 是调用合同的一部分。
- 存在非直观兼容性约束、幂等要求或关键设计决策。

```sh
# ----------------------------------------------------------------------
# _pkg_find_root — 从当前目录向上查找最近的 package.json 所在目录
#
# 设计意图：
#   交互选择脚本时以 package.json 所在目录作为执行目录，避免从子目录运行时
#   相对路径解析漂移。
#
# 参数：无。
# 输出：
#   stdout — package.json 所在目录的绝对路径。
# 返回码：
#   0 — 找到 package.json。
#   1 — 到达文件系统根目录仍未找到。
# ----------------------------------------------------------------------
_pkg_find_root() {
  ...
}
```

共同规则：

- 摘要、`参数：`、`返回码：`必需。
- `输出：`只描述 stdout/stderr；不再使用“返回值”表示输出。
- `副作用：`描述环境、全局状态、文件、目录或终端状态变化。
- `设计意图：`只解释为什么采用当前方案，不复述函数步骤。
- 无参数写 `参数：无。`；多个简单参数可同行，复杂参数逐行。
- 嵌套函数的整段注释与函数定义保持相同缩进。

### 4. 局部实现说明

```sh
# 使用机器可读输出，避免 ANSI 样式混入真实会话名。
sessions=$(zellij list-sessions --no-formatting)
```

规则：

- 说明原因、约束、异常行为或不可见副作用。
- 禁止逐句翻译命令、编号记录临时开发步骤或保留“关键修改”等历史痕迹。
- 使用中文全角标点；命令、变量、路径和协议名保持原文。

## 字段与标点合同

- 字段：`参数：`、`输出：`、`返回码：`、`副作用：`、`设计意图：`。
- 条目：`$1 — ...`、`stdout — ...`、`0 — ...`。
- 中文句子使用 `，`、`。`、`：`；代码标识符使用反引号仅限 Markdown 规范文档，Shell 注释中直接书写。
- 同一字段只有一项时允许同行；多项时换行缩进两个空格。

## 迁移策略

1. 先写规范并链接索引，固定模板后再迁移代码注释。
2. 按 `deploy.sh`、`shared.d`、`bash.d`、`zsh.d` 顺序迁移，避免同一文件多轮往返。
3. 每个文件先补文件头，再划分顶层主题，最后统一函数契约和局部说明。
4. 保留所有非注释行原样；特别保留工作区中 `node.sh` 的 pnpm 功能改动。
5. 不修改归档、生成物或其它包。

## 验证与回滚

- 编辑前在仓库外保存目标文件快照或等价的非注释行摘要。
- 编辑后比较目标文件的非注释、非空白行，必须完全一致。
- 对 `.sh` 运行 Bash 语法检查，对 `.zsh` 运行 Zsh 语法检查。
- 检查旧式章节标题、旧字段名和中英文标点混用是否仍存在。
- 发生误改时只回退本任务新增的注释 hunk；禁止使用整文件 checkout 覆盖用户现有 `node.sh` 改动。

## 取舍

- 不对所有函数使用完整块：函数密集文件会产生大量无信息量边框。
- 不对配置章节使用三行块：会与复杂函数外形冲突。
- 不新增 lint：当前仓库没有注释 AST 或格式门禁，引入工具的成本超过本次纯注释规范收益。
